# 인물 중심 영상 자동 크롭 시스템 구조도 및 설명

## 개요
본 시스템은 줌된 영상과 노줌 영상 두 개의 MP4 파일을 입력받아, 줌된 영상에서 인물을 디텍션하고, 그 정보를 처리하여 노줌 영상에서 인물 중심의 완벽한 영상을 생성하는 파이프라인입니다.

## 상세 처리 과정 설명

### 1. 오브젝트 디텍션 (VideoDetectFacade.kt)

**역할**: 줌된 MP4 영상에서 프레임별로 인물을 디텍션하여 바운딩박스 로그를 생성합니다.

**주요 코드 위치**:
- `app/src/main/java/com/echoshot/app/mp4detact/VideoDetectFacade.kt`
- `app/src/main/java/com/echoshot/app/mp4detact/models/yolo/YoloTflite.kt`

**처리 과정**:
1. MediaCodecOesDecoder로 MP4 프레임을 디코딩
2. GlLetterboxFbo로 640×640 정사각형으로 리사이즈 (letterbox 처리)
3. YoloTflite 모델로 인물 디텍션 수행
4. 디텍션 결과를 원본 좌표계로 역변환
5. JSONL 형식으로 로그 저장 (프레임 인덱스, 타임스탬프, 바운딩박스, 줌 정보)

**핵심 함수**:
```kotlin
// VideoDetectFacade.kt
suspend fun run(
    uri: Uri,
    onProgress: (frameIdx: Int, ptsMs: Long) -> Unit,
    onDetections: (frameIdx: Int, ptsMs: Long, list: List<Detection>) -> Unit
)
```

### 2. 바운딩박스 로그 처리 및 스무딩 (merge_offline_logs.py)

**역할**: 디텍션 로그를 처리하여 노이즈를 제거하고 부드러운 궤적을 생성합니다.

**주요 코드 위치**:
- `app/src/main/python/merge_offline_logs.py`

**처리 과정**:

#### 2-1. 인물 정렬 (L1/L2/L3)
- 첫 프레임: 면적 내림차순으로 L1/L2/L3 배정
- 이후 프레임: 직전 프레임과 IoU로 유사도 계산하여 매칭
- EMA 앵커로 장기 추적 안정성 확보

#### 2-2. 노이즈 제거
- 오버랩 윈도우(예: 10프레임) 평균 대비 이탈 감지
- 절대 임계값(예: 100px) 또는 상대 임계값(대각선의 15%) 초과 시 노이즈로 판단
- 노이즈 프레임을 None으로 마스킹

#### 2-3. 선형 보간
- None 구간을 선형 보간으로 채움
- 앞/뒤 가장자리는 근처 유효값으로 채움

#### 2-4. 이동평균 스무딩
- 소형 이동평균 윈도우(예: 3프레임)로 최종 부드럽게 처리

**핵심 함수**:

### 3. 칼만 필터 및 RTS 스무더 (make_log_pipeline.py)

**역할**: 고급 필터링 기법으로 더욱 부드럽고 정확한 궤적을 생성합니다.

**주요 코드 위치**:
- `app/src/main/python/make_log_pipeline.py`

**처리 과정**:

#### 3-1. 칼만 필터 (Kalman Filter)
- **상태 벡터**: [cx, cy, w, h, vx, vy, vw, vh] (중심점, 크기, 속도)
- **예측 단계**: 이전 상태와 속도로 다음 프레임 예측
- **업데이트 단계**: 관측값(디텍션 결과)과 예측값을 가중 평균
- **아웃라이어 제거**:
  - IoU 게이트: 예측 박스와 관측 박스의 IoU가 임계값(0.05) 이상
  - 마할라노비스 거리 게이트: 통계적 이상치 제거

#### 3-2. RTS 스무더 (Rauch-Tung-Striebel Smoother)
- 칼만 필터의 앞→뒤 필터링 결과를 뒤→앞으로 다시 스무딩
- 미래 정보를 반영하여 더 부드러운 궤적 생성

#### 3-3. 직선 + 코너 이음 처리
- RDP 알고리즘으로 직선 구간과 코너 구간 분리
- 직선 구간은 그대로 유지 (자연스러운 움직임 보존)
- 코너 구간만 Hermite 보간으로 부드럽게 이음

**핵심 함수**:

### 4. 비율 고정 및 좌표계 변환

**역할**: 바운딩박스를 9:16 비율로 고정하고, 줌 좌표계를 노줌 좌표계로 변환합니다.

**주요 코드 위치**:
- `app/src/main/python/merge_offline_logs.py` - `_enforce_9x16_height_first()`, `_center_unzoom_xyxy()`

**처리 과정**:

#### 4-1. 비율 고정 (9:16)
```python
def _enforce_9x16_height_first(box, W, H):
    h = y2 - y1  # 높이 기준
    target_w = h * 9.0 / 16.0  # 가로 = 높이 × 9/16
    # 화면 경계 내로 클램프
```

#### 4-2. 줌 좌표계 → 노줌 좌표계 변환
```python
def _center_unzoom_xyxy(box, W, H, z):
    cx, cy = W/2, H/2  # 화면 중심
    # 중심 기준 역변환
    x1' = cx - (cx - x1) / z
    y1' = cy - (cy - y1) / z
    x2' = cx - (cx - x2) / z
    y2' = cy - (cy - y2) / z
```

**수학적 원리**:
- 줌은 화면 중심을 기준으로 확대/축소
- 줌 레벨 z일 때, 화면상 좌표 x는 실제로는 (cx - (cx - x) / z) 위치에 해당
- 이를 역으로 계산하여 노줌 좌표로 변환

### 5. 패딩 적용

**역할**: 바운딩박스 주변에 여유 공간을 추가하여 인물이 잘리지 않도록 합니다.

**주요 코드 위치**:
- `app/src/main/java/com/echoshot/app/FrameCropper.kt` - `cropAll()` 메서드 내부

**처리 과정**:

```kotlin
val paddedFrames = if (paddingFactor == 1f) filled else filled.map { f ->
    val cx = (f.x1 + f.x2) * 0.5  // 중심점
    val cy = (f.y1 + f.y2) * 0.5
    val w = (f.x2 - f.x1) * paddingFactor  // 크기 확장
    val h = (f.y2 - f.y1) * paddingFactor
    f.copy(
        x1 = cx - w * 0.5,  // 새로운 박스
        y1 = cy - h * 0.5,
        x2 = cx + w * 0.5,
        y2 = cy + h * 0.5
    )
}
```

**일반적인 paddingFactor 값**:
- 인물 중심 모드: 1.5배
- 와이드 모드: 2.5배
- 기본값: 2.0배
- 사용자 요구사항: 3.0배

## 주요 알고리즘 및 기술

### 1. YOLO 디텍션
- **모델**: YOLOv8n (TensorFlow Lite)
- **입력**: 640×640 RGB 이미지
- **출력**: 바운딩박스 (x1, y1, x2, y2), 신뢰도 점수
- **후처리**: NMS (Non-Maximum Suppression), 신뢰도 임계값 필터링

### 2. 칼만 필터
- **상태 모델**: 선형 동역학 모델 (위치 + 속도)
- **과정 잡음**: 위치 25px, 속도 200px/frame
- **관측 잡음**: 35px
- **게이팅**: IoU ≥ 0.05, 마할라노비스 거리 ≤ 10.0

### 3. RTS 스무더
- **역방향 필터링**: 미래 정보를 반영하여 더 부드러운 궤적 생성
- **C¹ 연속성**: 속도 연속성 보장

### 4. RDP 알고리즘 (직선 단순화)
- **목적**: 직선 구간과 코너 구간 분리
- **허용 오차**: 위치 8px, 크기 1.5% (로그 도메인)
- **최소 세그먼트 길이**: 0.18초
- **코너 전환 길이**: 0.10초

### 5. Hermite 보간
- **목적**: 코너 구간을 부드럽게 이음
- **C¹ 연속성**: 위치와 속도 모두 연속

### 6. OpenGL ES 크롭
- **텍스처 타입**: GL_TEXTURE_EXTERNAL_OES (SurfaceTexture)
- **크롭 방법**: 텍스처 좌표 변환 행렬
- **성능**: GPU 가속으로 실시간 처리 가능

1. **이중 영상 입력 시스템**: 줌 영상과 노줌 영상을 동시에 활용하여 디텍션 정확도와 최종 영상 품질을 모두 확보

4. **동적 크롭**: 프레임별로 다른 크롭 박스를 적용하여 인물이 항상 중앙에 위치하도록 보장

5. **실시간 처리**: OpenGL ES와 MediaCodec을 활용한 하드웨어 가속 처리
